# Light inventory/workshop and collider-free world visuals

Inventory tiles have one subtle background, no nested row/button border, small lock glyphs with the original independent 44-unit hit areas, and permanently available inline wear/compare text actions. Mobile tabs use an underline; filter width is 64 units and sorting is a 44-unit icon target with a roughly 24-unit visual. Sorting opens compact options with the current option underlined. Tile stride is 94 units, preserving at least six fully visible tiles on the smallest tested landscape before comparison opens. Left equipment-slot icons no longer have button boxes.

Workshop tabs are 88-unit text targets with an underline. Footer has one 112-unit return action and compact secondary links; controls do not stretch to fill tablet width. Content actions measure their captions and retain 48-unit hit height. Desktop inventory also uses lightweight cards and inline actions. Input debouncing, GUI.enabled and scroll event suppression remain.

All remaining runtime GameObject.CreatePrimitive calls were visual-only: enemy health Quad, companion health Cube, death-mote Sphere and ground-loot decoration. Each formerly removed its implicit collider. They now use ProceduralVisuals.Create. A cached explicit Quad (negative-Z winding, unit dimensions, UVs and normals) was added; other shapes reuse existing collider-free visual recipes. Existing cache reset owns mesh destruction. No physical actor/navigation collider code was removed. Preview retains its preceding isolated mesh/recovery implementation.

Checks: adaptive inventory/toolbar hit geometry, source entry contracts, actual scroll and Back replay, actual shared Quad/Create under managed component boundaries without collider types, preview lifecycle and old-code reproduction, reward UI, and whole runtime Unity-reference compilation. These do not prove Unity rendering or device usability. Latest Mac QA is for the preceding ca79c6d: inventory preview, merchant-only entry, bottom HP, text objectives and iPad title passed; EnemyController.HealthQuad still errored there and is fixed only in this new candidate. Rebuild once when Mac load permits; main remains held for QA.
